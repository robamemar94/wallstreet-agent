# 0. RESUMEN EJECUTIVO

## 0.1 Qué es Microsoft realmente

Microsoft no debe analizarse como una colección de productos
independientes. Su activo económico central es un **ecosistema
tecnológico empresarial integrado** que cubre distintas capas del stack:

**productividad → identidad → seguridad → datos → aplicaciones →
desarrollo → cloud → IA.**

La compañía controla o participa en:

-   Microsoft 365
-   Teams
-   Entra
-   Defender
-   Purview
-   Azure
-   Dynamics
-   GitHub
-   Fabric
-   Foundry
-   Copilot
-   Gaming
-   Search

La característica importante no es que Microsoft tenga muchos productos,
sino que varios de ellos están conectados dentro del mismo entorno
empresarial.

Una organización puede utilizar Microsoft 365 para productividad, Entra
para identidad, Defender para seguridad, Azure para infraestructura,
GitHub para desarrollo, Fabric para datos, Dynamics para aplicaciones y
Copilot/Foundry para IA.

Cuantas más capas utiliza una empresa, más difícil y costoso resulta
sustituir el conjunto.

------------------------------------------------------------------------

## 0.2 Tesis central

La tesis es que **Microsoft puede convertirse en una de las principales
plataformas de monetización de la IA empresarial porque ya controla una
combinación extraordinaria de distribución, workflows, identidad,
seguridad, datos, cloud y ecosistema de desarrolladores sobre la que la
IA necesita operar.**

La cadena económica que debemos demostrar durante los próximos años es:

**base instalada**

→ **Copilot / Agents**

→ **más uso de IA**

→ **más consumo Azure / Foundry**

→ **más datos y necesidad de infraestructura**

→ **más necesidad de identidad, seguridad y governance**

→ **mayores switching costs**

→ **mayor gasto tecnológico por cliente**

→ **mayores ingresos y beneficios**

→ **mayor FCF/share**

La tesis **no depende de que OpenAI sea el ganador definitivo de la
IA**. Microsoft intenta posicionarse también como plataforma que permite
utilizar diferentes modelos y construir aplicaciones y agentes sobre
Azure/Foundry.

------------------------------------------------------------------------

## 0.3 La gran pregunta de inversión

La demanda de IA ya no es la principal incógnita.

En FY2026 Microsoft comunicó:

-   Azure superó los $100B de ingresos anuales.
-   Azure creció aproximadamente un 41% en FY2026 y un 43% en Q4.
-   Microsoft Cloud alcanzó $214,4B de ingresos y creció un 27%.
-   Commercial RPO alcanzó aproximadamente $678B.
-   Microsoft comunicó más de 30 millones de paid seats de Microsoft 365
    Copilot.
-   Foundry alcanzó aproximadamente 100.000 clientes.

La gran pregunta pasa a ser:

> **¿Qué retorno económico obtendrá Microsoft sobre el enorme capital
> que está desplegando para satisfacer esta demanda?**

La cadena crítica es:

**Capex → capacidad → revenue → margen → FCF → ROIC.**

Esta es actualmente la zona de mayor incertidumbre de nuestra tesis.

## 1.6 Microsoft 365: evidencia de monetización de la base instalada

En FY2026, Microsoft 365 Commercial Cloud creció aproximadamente
**17%**, mientras los seats crecieron alrededor de **6%**.

El diferencial de aproximadamente **11 puntos porcentuales** es una
evidencia de que el ingreso por usuario y/o el mix están aumentando.

No debemos atribuir mecánicamente esos 11 puntos a Copilot. También
intervienen:

-   pricing;
-   mix;
-   E5;
-   Security;
-   otros servicios.

Pero sí demuestra un mecanismo fundamental:

> **Microsoft está aumentando el valor económico de la base instalada
> más rápido que el número de usuarios.**

Esto es exactamente el tipo de mecanismo que buscamos en un compounder
maduro.

# 2. MOAT, COMPETENCIA Y DISRUPCIÓN

## 2.1 El moat no es "ser líder"

No asignamos moat por:

-   tamaño;
-   liderazgo;
-   reconocimiento de marca;
-   historia.

El moat debe explicarse mediante mecanismos económicos observables.

En Microsoft identificamos una combinación de:

1.  switching costs;
2.  distribución;
3.  ecosystem;
4.  identity;
5.  security;
6.  developer ecosystem;
7.  cloud scale;
8.  enterprise trust.

La ventaja procede de la combinación, no de un único activo.

------------------------------------------------------------------------

## 2.2 Switching costs

Un cliente empresarial grande que utiliza Microsoft 365, Entra,
Defender, Azure, Dynamics y otros servicios no puede sustituir Microsoft
instalando otro producto.

Debe migrar potencialmente:

-   usuarios;
-   datos;
-   identidad;
-   workflows;
-   integraciones;
-   seguridad;
-   políticas;
-   aplicaciones;
-   procesos internos;
-   formación.

El coste es:

-   técnico;
-   operativo;
-   financiero;
-   organizativo.

Esto constituye un switching cost real.

------------------------------------------------------------------------

## 2.3 Distribución

Una empresa AI independiente tiene que construir:

**producto → confianza → cliente → integración → distribución.**

Microsoft parte de:

**cliente → workflow → identidad → datos → distribución.**

Eso reduce:

-   CAC;
-   fricción de adopción;
-   tiempo de implementación.

La ventaja puede ser especialmente importante cuando la AI se integra
directamente en el software que los empleados ya utilizan.

------------------------------------------------------------------------

## 2.4 Ecosistema

La utilización conjunta de:

**M365 + Entra + Security + Azure + GitHub + Fabric + Dynamics**

puede crear efectos de complementariedad.

Cada producto individual puede ser sustituible.

El conjunto es mucho más difícil de sustituir.

La métrica que debemos vigilar no es únicamente clientes.

Debemos intentar observar:

**cross-sell y profundidad de utilización por cliente.**

------------------------------------------------------------------------

## 2.5 Identity como moat

Identity es una capa estratégica.

Si los agentes adquieren capacidad de acción, Microsoft puede controlar:

-   identidad;
-   permisos;
-   acceso;
-   policy;
-   governance.

Esto puede crear un nuevo switching cost.

------------------------------------------------------------------------

## 2.6 Security como moat

Más AI implica potencialmente:

-   más endpoints;
-   más agentes;
-   más datos;
-   más superficie de ataque;
-   más permisos.

Por tanto:

**AI → mayor complejidad → mayor necesidad de security/governance.**

Microsoft puede vender esta seguridad sobre el mismo stack.

------------------------------------------------------------------------

## 2.7 Developers

GitHub permite conectar:

**developers → code → CI/CD → applications → Azure.**

Copilot añade AI directamente al workflow del desarrollador.

Esto crea una segunda vía de distribución y lock-in distinta de M365.

------------------------------------------------------------------------

## 2.8 AWS

AWS posee ventajas en:

-   escala;
-   infraestructura;
-   experiencia cloud;
-   amplitud de servicios;
-   base instalada.

Microsoft compite con:

-   M365;
-   Entra;
-   Security;
-   GitHub;
-   Dynamics;
-   Copilot;
-   Foundry;
-   Fabric.

La batalla no debe entenderse únicamente como:

**Azure vs AWS compute.**

La cuestión económica más importante es:

> **qué plataforma se convierte en el stack tecnológico principal de la
> empresa.**

------------------------------------------------------------------------

## 2.9 Google

Google tiene fortalezas especialmente relevantes en:

-   investigación AI;
-   modelos;
-   data;
-   cloud;
-   search;
-   developer ecosystem.

La amenaza consiste en que Google consiga integrar AI suficientemente
bien para reducir la ventaja de distribución de Microsoft.

Microsoft, por su parte, tiene una posición especialmente fuerte en
software empresarial y productividad.

------------------------------------------------------------------------

## 2.10 OpenAI

OpenAI es simultáneamente:

-   socio;
-   proveedor;
-   activo financiero;
-   potencial fuente de concentración;
-   potencial competidor indirecto.

Microsoft comunicó una participación aproximada del 25% sobre base
as-converted y aproximadamente $24,1B de revenue FY2026 procedente de
acuerdos comerciales con OpenAI.

La tesis no debe reducirse a:

**Microsoft = OpenAI.**

La arquitectura de Foundry y el soporte de múltiples modelos son
importantes precisamente porque permiten una tesis más amplia.

------------------------------------------------------------------------

## 2.11 Disrupción por agentes

### Amenaza

Los agentes pueden desacoplar al usuario de aplicaciones individuales.

### Cadena de riesgo

**agents**

→ interacción transversal

→ menor dependencia de aplicaciones concretas

→ menor switching cost

→ mayor competencia

→ menor pricing power.

### Contrafuerza Microsoft

Microsoft puede intentar convertirse en:

**identity + data + security + governance + cloud + agent platform.**

Por tanto, la disrupción puede reducir el valor de una capa del stack
mientras aumenta el valor de otra.

------------------------------------------------------------------------

## 2.12 Disrupción por commoditización de modelos

Si los modelos se vuelven más baratos:

### Negativo

Menor diferenciación y pricing de algunos productos AI.

### Positivo

Menor coste de inferencia puede aumentar el uso.

→ más tokens

→ más consumo Azure.

La variable decisiva es:

> **quién captura el valor económico de la commoditización.**

------------------------------------------------------------------------

## 2.13 Moat durability

### Moat Durability Score: **90/100**

Este score es auxiliar y **no representa una probabilidad**.

### Fortalezas

-   switching costs;
-   distribución;
-   ecosystem;
-   identity;
-   security;
-   cloud;
-   developers;
-   enterprise trust.

### Vulnerabilidades

-   agents pueden desacoplar aplicaciones;
-   cloud competition;
-   open source;
-   AI commoditization.

### Conclusión

El moat actual es suficientemente amplio y diversificado para considerar
plausible su duración durante 10–20 años, aunque su forma probablemente
cambiará.
